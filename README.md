# PaykiTodo

[![Latest release](https://img.shields.io/github/v/release/HoshiTakyobu/PaykiTodo?label=release)](https://github.com/HoshiTakyobu/PaykiTodo/releases/latest)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Android](https://img.shields.io/badge/platform-Android-green.svg)](app)
[![CI](https://github.com/HoshiTakyobu/PaykiTodo/actions/workflows/android-ci.yml/badge.svg)](https://github.com/HoshiTakyobu/PaykiTodo/actions/workflows/android-ci.yml)

PaykiTodo 是一个以 **强提醒、本地可控、日程与待办一体化** 为核心的 Android 个人效率助手，可用于管理待办、DDL、日程、倒数日和规划草稿。

项目采用用户需求与人工验收主导的 **AI 辅助 vibe coding** 方式持续开发：产品取舍、交互反馈和发布决策由维护者负责，AI 工具参与实现、测试、排障和文档维护。它不是限定于 Android 14 的实验项目，当前安装包支持 Android 8.0 及以上系统。

它面向这样的使用场景：

- 不希望重要 DDL 被普通通知淹没；
- 需要把待办、日程、倒数日和规划草稿放在同一套本地数据里；
- 希望在手机上使用，同时能通过同局域网电脑网页端做较高效的编辑；
- 希望数据尽量留在本机，并能自行备份、恢复和导出。

> 当前项目仍是个人维护型应用。提醒可靠性会受到 Android 版本、厂商 ROM、电池策略、通知权限、精确闹钟权限等因素影响；不要把它当作医疗、安全生产或法律合规场景的唯一提醒来源。

## 功能概览

### 1. 每日看板

- 聚合显示今日待办、今日日程、明日日程和关键倒数目标。
- 手机每日看板保留浅色 / 深色专属山景背景、原有森林绿 / 陶土色主题和定制问候字体；内容卡片维持紧凑层级。
- 已结束日程会从今日日程计数中排除，正在进行的日程会突出显示。
- 无 DDL 的活动待办默认作为今日待办处理，适合“今天想做但还没定具体时间”的事项。
- 支持从看板进入待办、日历、规划台等具体页面。

### 2. 待办与 DDL

- 支持标题、备注、多分组、DDL、提醒方式、多提醒时间、循环任务和倒数日标记；提醒时间可从 5/15/30 分钟、1/2 小时、1/2 天预设中多选，也可输入自定义时间。
- 待办和日程可分别勾选全屏提醒与通知栏提醒；两项都不选即不提醒，同时勾选则全屏界面与通知栏内容共同生效。
- 在每日看板或待办页长按任意待办即可进入批量选择；顶栏会显示已选数量，完成 / 取消操作固定悬浮在屏幕底部，向下浏览长列表时无需返回顶部。取消会写入历史记录，循环待办批量取消只影响当前选中的实例。
- 待办页的分组筛选改为近全宽、限高的下拉菜单，菜单顶部提供“管理分组”，可从同一入口新建、编辑和删除分组。
- 待办页深色模式使用分层的深蓝灰工作区而非纯黑底板；长列表渲染隔离了电脑同步轮询和每日看板时钟，并减少单卡绘制层级、重复颜色与日期计算。
- 待办详情预览中“取消待办”和“删除”保持分离：取消会进入历史记录，删除是硬删除；循环待办取消时会用“仅此一次 / 从这次开始 / 整个系列”明确选择影响范围。
- 待办详情和编辑器负责取消、修改 DDL、循环范围等复杂处理；全屏提醒页只保留完成和固定延后。
- 支持批量添加待办，以及自然日期/时间输入，例如 `16:30`、`明天 16:30`、`5.28 23:59`。
- 待办和日程编辑器只在右上角“完成”时提交；系统返回、顶部取消或下滑关闭会直接丢弃本次草稿，不再弹出“放弃本次编辑”确认。

### 3. 日历与日程

- 支持普通日程、全天日程、循环日程、地点、备注、颜色、提醒和倒数日标记。
- 支持单日、三日、月视图和列表等日历浏览方式。
- 时间轴可点击空白区域快速创建日程。
- 持续多天的日程、进行中日程和普通日程使用不同视觉处理。
- 日程详情预览支持“取消日程”和“删除”：取消会进入历史记录，删除是硬删除；循环日程取消/删除前会先选择作用范围。
- 日程没有“完成”状态；详情页支持创建副本，把原日程参数带入新增界面后修改时间等字段。
- 开启打卡追踪后可设置独立签到提醒；普通提醒和签到提醒会合并去重，并随循环日程、多时间段日程和周模板保存。
- 日程与待办分组使用手机/电脑一致的 12 色预设顺序。

### 4. 强提醒能力

- 使用 `AlarmManager` 做提醒调度。
- 全屏提醒与通知栏提醒是独立渠道，并支持锁屏唤醒、响铃、震动和工作模式；工作模式或闹钟模式不会强行打开未勾选的全屏渠道。
- 在提醒页完成待办会移除通知；延后或确认本次提醒后，仅在勾选了通知栏提醒时保留可划走的普通通知，点击直接进入事项预览。
- 提供提醒链路诊断与短延迟全屏测试入口，会显示通知、精确闹钟、全屏权限、电池优化和辅助功能兜底状态。
- 支持内置提示音与系统通知提示音选择。
- 全屏待办提醒页保持极简，只提供“我已完成”和“延后 10 分钟”；取消待办、修改 DDL 等复杂操作回到待办详情/编辑器处理。
- 完成或取消待办会同步移除对应通知、前台提醒服务、响铃/震动和无障碍浮层；失效通知不会再打开崩溃页面。
- 支持重要 DDL 的闹钟模式：提醒可持续响铃/振动，未处理后降级为通知并进行有限重试。

### 5. 规划台

规划台是 PaykiTodo 的“上游备忘录”，用于先自由写计划，再把明确事项识别为正式待办或日程。

- 支持多篇规划文档。
- 手机端和电脑端都以大文本备忘录为主入口，不再要求学习井号标签、大纲节点或 Markdown 语法。
- 支持自然 DDL、轻量日程、地点、无 DDL 待办和缩进子任务识别。
- 支持从分享、拍照、语音和图片识别入口快速捕获内容。
- 识别结果先进入预览页，用户勾选和修正后才会导入正式待办或日程。
- 已导入内容通过内部映射记录去重，不再往用户原文里追加可见井号标记。

### 6. 可选 AI 识别

- 支持配置多个 OpenAI-compatible AI 源。
- AI Key 和 Base URL 只保存在本机设置中，备份 JSON 不导出这些敏感字段。
- AI 源增删改、启停、排序以及日报 / 周报计划先保存在页面草稿中，只有点击右上角“完成”才一次性写入；直接返回不会保存本次修改。
- 模型测试只向当前接口发送一条固定消息，不自动重试或切换地址；遇到 HTTP 429 会立即停止，避免短时间重复测活。
- AI 和在线语录请求统一使用当前 Windows 开发环境对应的 Codex CLI User-Agent，不再向服务端暴露 Android 设备型号和系统构建号。
- 规划台识别会优先调用启用的 AI 源；失败、超时或未配置时自动回退到本地规则解析器。
- AI 识别结果进入预览页，用户确认后才会导入。
- 电脑端 Web 规划台与手机端共用同一套 AI 优先 / 本地兜底链路。
- 日报 / 周报即使 AI 调用失败也会生成本地兜底内容；应用启动时会补查最近一次错过的周期，并持续续排下一次任务。
- 电脑端“AI 报告”页可查看日报 / 周报是否启用、下次触发时间、精确 / 非精确调度、最近成功或失败原因及近期报告，不显示 API Key 或 Base URL。

### 7. 电脑同步 / 局域网网页端

- 手机端可开启同局域网网页控制台。
- 电脑浏览器访问手机提供的本地地址后，可以查看每日看板、编辑待办、编辑日程、使用规划台和检查 AI 报告运行状态。
- 手机端会优先推荐活动 Wi-Fi、热点或物理网卡地址，支持校园网常见 CGNAT / 校园公网 IPv4；移动数据、VPN、回环和链路本地地址仍会隐藏。校园网若开启终端隔离，地址虽可显示但电脑仍可能无法直连。
- 4 位访问密钥不区分大小写，网页输入会自动去空格并规范为大写。
- 网页端使用浅色轻量顶栏和紧凑连接状态；每日看板负责概览，待办页负责完整管理。
- 网页端日历按飞书日历参考图重做为左侧迷你月历 / 分组筛选与右侧全宽时间轴，提供日、周、月视图、搜索、日期跳转和分组显隐；不再使用页面标题卡或外层日历卡片。
- 网页端日程编辑器使用左侧表单、右侧单日时间轴预览的双栏窗口；保留提醒、签到提醒、循环、多时间段、地点、备注、分组、颜色和倒数日等 PaykiTodo 字段。
- 待办 / 日程提醒、签到提醒、创建副本和 12 色选择与手机端保持一致；日程编辑器按标题、时间、地点、提醒、备注、循环、分组 / 颜色组织字段。
- 网页端操作直接写入手机本机 Room 数据库。
- 同步功能没有云账号体系，不经过项目作者服务器。

### 8. Android 桌面小组件

- 今日看板 Widget：显示公告、问候、今日待办、今日日程和明日日程摘要。
- 倒数日 Widget：独立展示最近倒数目标，按分钟刷新。
- 小组件支持浅色 / 深色模式，并使用独立的暖白 / 深灰背景和卡片视觉。
- 点击待办区域进入待办，点击日程区域进入日历或对应详情。

### 9. 数据、备份与排障

- 本地 Room 数据库。
- JSON 备份与恢复。
- 崩溃日志查看与复制。
- 内置 Wiki / 使用说明。
- 数据健康检查与安全清理。

## 安装说明

### 从 GitHub Release 安装

1. 打开最新 Release：<https://github.com/HoshiTakyobu/PaykiTodo/releases/latest>
2. 下载 `PaykiTodo-*-release.apk`。
3. 在 Android 手机上允许当前浏览器或文件管理器“安装未知来源应用”。
4. 安装 APK。

注意：

- 如果手机上已经安装的是 debug 签名版本，可能无法直接覆盖安装 release 签名版本。
- debug 与 release 签名不同。要从 debug 切到 release，通常需要先在应用内导出备份，再卸载 debug 版，然后安装 release 版并导入备份。
- 卸载应用会删除本地数据；操作前先备份。

## 本地构建

### 环境要求

- Android Studio
- Android SDK 34
- JDK 17（推荐使用 Android Studio 自带 JBR）

### Debug 构建

```powershell
./gradlew.bat :app:assembleDebug
```

输出位置：

```text
app/build/outputs/apk/debug/
```

### Release 构建

Release 签名材料不属于仓库内容，必须只保存在本地：

```text
keystore.properties
release/PaykiTodo-release.jks
```

这两个路径已经在 `.gitignore` 中忽略。不要把真实密码、API Key、Token、私有 Base URL 或 keystore 提交到 Git。

可参考安全模板：

```text
keystore.properties.example
docs/templates/
```

构建命令：

```powershell
./gradlew.bat :app:assembleRelease
```

## 隐私与数据边界

PaykiTodo 当前是本地优先应用：

- 不要求账号登录。
- 默认不上传待办、日程、规划文档或备份数据到项目作者服务器。
- 电脑同步只在用户主动开启后，通过局域网访问手机端服务。
- AI 功能是可选项；只有用户配置并启用 AI 源时，规划台识别 / AI 报告相关文本才会发送到对应第三方模型服务。
- API Key、Base URL 等敏感配置只应保存在本机，不应进入 Git、截图、日志或公开 Issue。

详见：[`PRIVACY.md`](PRIVACY.md)。
