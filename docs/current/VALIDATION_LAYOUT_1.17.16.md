## 最小窗口宽度的计算

以**一小时标准日程格**为基准，而不是任意长度的日程（长短日程无法同时满足固定宽高比）：

```text
H = 48 × 正文字号 / 14
Wmin = max(900, ceil(204 + 36 + 16 + 时间轴宽度 + 滚动条宽度
                    + 7 × (1.5 × H + 7) + 16))
时间轴宽度 = 56 × 正文字号 / 14
```

204 是主导航，36／16 是日历边距，7 是每列日程间隙，末尾 16 预留窗口边框。默认 14 DIP 下下限为 **900 DIP**；实测 900-DIP 窗口七列约 80 DIP，每个一小时日程块约 73×46 DIP，宽高比约 **1.59**。同时检查 1138、1280 DIP 和 12／18／22 DIP 字号；创建与拖动使用同一个缩放后的小时高度，避免只缩画面却改变落点时间。

- Windows 原始字符串 XAML 的括号和 `Brush` 命名歧义导致编译失败，已修正。
- PowerShell 5 读取 UTF-8 脚本失败，改用 PowerShell 7；证据目录统一绝对路径，修正测试对路径分隔符的假设。
- 缩放后的日历算术曾间接初始化 WPF 资源，使非 UI 单测失败；创建／拖动纯函数改为显式接收小时高度。
- 宽屏设置内容意外居中，被回归检测后修正为左对齐。
- 日期选择器内部上下留白和大字号时间框最小高度曾造成文字裁切；按真实字形行高及单次内边距计算后，常规／最大字号和完整 UIA 复验通过。
- 旧测试仍假定三天周视图、旧色值、折叠色盘、普通文本摘要或始终退出的旧 EXE；按新要求更新断言与基线进程收尾，业务保存／取消断言保留。
- Android 一次漏导入 `heightIn`，一次条件块缩进触发 Lint；已修正并完整复跑。
- 手机色盘测量跨越了两次滚动，登录测试点击屏外入口，早期截图存在合成帧时序问题；改为同一视口测量、先滚动到入口并等待绘制后，15 项最终检查通过，最终截图重新核对。
