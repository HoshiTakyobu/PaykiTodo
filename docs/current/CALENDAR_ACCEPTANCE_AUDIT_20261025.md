# 日历与账号功能最终复核

日期：2026-10-25。核验基线：`f7f1590`，Android `1.17.1 / versionCode 393`、Windows `1.17.1.0`、Room `33`。本轮接续中断的最终检查，核对源码、测试原始结果、真实控件截图、数据保留及现有成品，没有修改产品行为或重建安装包。

## 结论

当前列明的核心日历与账号改进已实现，并有本地数据、控件和安装包证据。共享服务已经部署，但生产双账号在 Android 与 Windows 中完成邀请、接受、编辑、回应、撤权的完整流程仍未验收。因此不能把“本地实现完成”和“服务已部署”合并表述为全部功能、全部平台和全部协作场景均已完成验收。

后续的 [1.17.2 同步修复验收](VALIDATION_1.17.2.md)新增了真实 Windows 原生共享创建、个人快照隔离和数据保留证据，并重建客户端安装包。下文仍是 1.17.1 审计记录；双账号原生协作仍待手动验证码与后续验收，不能从单账号共享创建推定已完成。

## 仍未覆盖的能力与验证

- 参与者必须先成为共享日历已接受成员；组织者按现有服务契约固定为日历所有者。尚未实现任意外部参与者、独立日程组织者转移等更完整的协作模型。
- 已有单条日程 `BUSY/FREE` 字段和受限成员的忙闲投影；源码及服务路由未提供跨成员可用时段查询、排期建议的完整工作流。不能把一个忙闲选项当成忙闲排期功能。
- 当前共享日历通过账号邀请与成员权限访问；未发现独立订阅源管理或完整日历订阅工作流。会议室资源预约、冲突审批和视频会议创建/撤销服务也未形成实现链路。
- 生产双账号原生客户端协作、Windows 物理输入全流程和手机 OEM 场景仍缺直接证据。这些分别是验收缺口，不等于已证实功能失效。
- 上述扩展功能描述当前能力边界，不表示本次复核已新增开发范围或完成这些能力。
