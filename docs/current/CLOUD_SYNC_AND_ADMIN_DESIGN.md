# PaykiTodo 账号、云同步与管理员后台设计

## 文档状态

- 状态：`1.16.5` 本地验证基线，包含提醒服务降级、过往日程提醒语义、账号登录页视觉更新和管理员凭据显式轮换。
- 旧服务器代码 `server/paykitodo_sync_server.py` 继续为旧安装提供按设备 ID 的密文中转兼容。
- 新服务器代码 `server/paykitodo_cloud_server.py` 已实现账号、令牌、设备、版本化密文快照和管理员页面，默认监听 `127.0.0.1:18766`。
- Windows EXE 已拥有 DPAPI 保护的本地数据副本，可离线编辑并通过账号同步；手机 `18765` 仍是独立的 LAN 兼容模式。
- 管理后台未登录时显示站内登录页，使用 HttpOnly/Secure/SameSite 会话 Cookie；不再依赖浏览器原生 Basic Auth 弹窗。有效 Basic Auth 仅作为脚本兼容入口保留。
- 本文不包含账号密码、API Key、SSH 私钥、Cloudflare Token 或真实服务器地址之外的敏感凭据。

## 1. 产品边界

PaykiTodo 的每台设备都必须保留完整本地数据，Room / 本地数据库仍是设备离线时的可用副本。服务器的作用是：

1. 账号登录后保存一份跨设备同步副本；
2. 手机或 Windows 客户端完成一次本地写操作后，向服务器提交变化；
3. 另一台已登录设备拉取变化并更新自己的本地数据库；
4. 服务器到期、断网或 Cloudflare 故障时，手机仍可独立使用，局域网直连仍可直接操作手机本机数据。

服务器不能成为唯一数据源，也不能让客户端每次打开都依赖服务器才能看到待办或日程。

## 1.1 两套完全独立的连接模式

### 云端客户端模式（正式 Windows EXE）

手机端和 Windows EXE 都是独立客户端，各自保存一份完整的本地数据。两端通过账号登录服务器同步数据，正式数据流是：

```text
手机本地数据库 <-> PaykiTodo 服务器 <-> Windows EXE 本地数据库
```

Windows EXE 在这种模式下不连接手机的 `18765`，不依赖手机在线，也不承担手机 Web 服务职责。手机和电脑都可以在服务器暂时不可用时独立查看和编辑本地数据，网络恢复后再同步。

### 手机局域网模式（兼容入口）

用户主动在手机上开启“连接电脑”后，手机临时监听局域网 `18765`。电脑浏览器通过该地址直接访问手机提供的 Web 页面，所有修改直接写入手机本地数据库：

```text
电脑浏览器 -> 手机:18765 -> 手机本地数据库 -> 手机同步服务器
```

这条路径没有独立的电脑本地数据库，也不经过正式的账号客户端同步协议。它与正式 Windows EXE 是两码事，必须在 UI、代码和文档中分开标注。

## 2. 目标组件

### 2.1 账号服务

第一阶段已实现接口：

- `POST /v2/auth/register`
- `POST /v2/auth/login`
- `POST /v2/auth/refresh`
- `POST /v2/auth/logout`
- `GET /v2/devices`
- `DELETE /v2/devices/{deviceId}`

密码当前使用带随机盐和服务端 pepper 的 `scrypt` 保存摘要。访问 Token 短期有效，Refresh Token 只存哈希并按设备轮换/撤销；登录和注册有限流，安全动作写入审计表。管理员 MFA、找回密码和邮件验证仍属于后续安全增强。

### 2.2 同步服务

第一阶段已实现接口：

- `GET /v2/sync/status`：返回服务器 revision 和快照元数据；
- `GET /v2/sync/snapshot`：下载当前账户的端到端加密快照；
- `PUT /v2/sync/snapshot`：携带 `If-Match` 基础 revision 和幂等操作 ID 上传快照。

第一阶段仍是整包同步，但通过 revision 和 `If-Match` 阻止“最后上传静默覆盖”。本地无待上传修改时会自动拉取；两端都修改时停止并提示冲突。字段级操作日志、删除墓碑和自动合并仍属于下一阶段。

### 2.3 数据与加密

- 客户端生成随机账户数据密钥；服务器只保存加密快照和加密变更包，不能读取标题、地点、备注或 API Key。
- 每台设备保存自己的设备密钥；账户数据密钥通过设备公钥分别包装，新增设备必须经过已登录设备确认或一次性恢复码授权。
- 认证 Token 和数据加密密钥必须分离。注销、撤销设备或修改登录凭据不能直接把旧设备重新变成可信设备。
- 同步包应有版本、客户端 ID、操作 ID、基础 revision、创建时间、校验和与幂等键；重复提交不能重复写入。
- 迁移包 `.paykibak` 与云同步包分开处理，导入导出规则继续排除 AI API Key、电脑同步密钥、服务器 Secret 和本地文件授权状态。

## 3. 冲突与本地一致性

所有写操作按以下顺序执行：

1. 先写本地 Room；
2. 本地事务成功后把操作写入待上传队列；
3. 网络可用时向服务器提交；
4. 服务器按 revision 接收并返回冲突或已合并结果；
5. 客户端在后台应用其他设备的操作，并刷新提醒、Widget 和日历缓存。

待办、日程、分组、规划文档、循环模板和取消/删除墓碑需要明确各自的合并键。删除不能立即丢掉墓碑，否则离线设备重新上传旧对象时会把已删除事项复活。无法安全字段合并时必须显示冲突列表，不能静默使用“最后写入覆盖”。

## 4. Windows EXE 目标

Windows 客户端不是手机 `18765` 网页的另一个名字，而应是拥有本地数据副本的独立客户端。需要严格区分两条连接路径：

- 手机 LAN 模式：手机启动局域网 Web 服务并监听手机自己的 `:18765`；电脑浏览器访问该地址，当前 Windows WebView2 壳的“手机 LAN”模式也只是把这个网页嵌入 EXE。它直接读写手机本地数据，不经过账号服务器。
- 云同步模式：独立 Windows EXE 在本机保存自己的数据，通过账号登录后主动向服务器的 HTTPS API 发起请求；EXE 本身不监听 `18765`，也不需要开放电脑入站端口。服务器端完整 API / Admin 服务目标监听 `127.0.0.1:18766`，公网由 Cloudflare / Nginx 的 `:443` 转发。

目标 Windows 客户端应具备：

- 账号注册 / 登录 / 退出和设备撤销；
- 本地数据库副本，断网时仍能查看和编辑；
- 与手机相同的待办、日程、提醒、循环、规划台字段契约；
- 每次本地修改后立即排队同步，后台按分钟兜底拉取；
- 服务器不可用时显示“本地已保存，等待同步”，而不是阻止编辑；
- 手机与电脑在同一局域网且用户开启“连接电脑”时，继续支持浏览器直接操作手机本机数据；这条兼容路径才使用手机的 `18765`，不应与云同步模式混用。

现有 WebView2 壳和 LAN Web API 可以复用界面契约，但不能把手机 HTTP API 当成云端协议。应先抽出跨端 DTO、同步操作模型和本地仓储，再将 WebView2 作为 Windows 本地客户端的界面。

## 5. 管理员后台

管理员域名应指向单独部署的 PaykiTodo 管理入口，不是 1Panel 域名的别名，也不应复用 1Panel 的管理页面。1Panel 继续只用于服务器管理；服务器可以通过 1Panel 管理一个独立的 PaykiTodo API / Admin 容器或进程，并由 Nginx / OpenResty 为管理员域名配置独立的反向代理站点。

它不应复用普通用户登录页：

- 管理员单独账号、MFA、短会话、IP / 设备审计和高风险操作二次确认；
- 用户列表只展示账号状态、创建时间、最近活跃、设备数、同步状态和存储用量等必要元数据；
- 默认不显示用户待办、日程、备注等明文内容；如确需支持诊断，应使用用户主动授权的临时、可审计支持会话；
- 支持禁用账号、撤销设备、清理异常会话、查看同步失败和限流事件；
- 管理员操作写入不可篡改的审计日志，禁止把密码、Token、API Key 或解密密钥写入日志。

## 6. Cloudflare 与服务器上线前置条件

本仓库不能代替域名所有者完成 Cloudflare 登录。正式上线前需要用户在 Cloudflare 控制台确认并完成：

1. 确认管理员域名所属 Zone 和 hostname 的所有权；
2. 选择 DNS A/AAAA 记录 + 橙云代理，或优先选择 Cloudflare Tunnel，避免直接暴露源站；
3. 开启 SSL/TLS `Full (strict)`，使用源站证书或 Tunnel，不允许明文 HTTP 作为账号接口；
4. 为登录、注册、同步上传和管理员路径设置 WAF / Rate Limiting；
5. 源站防火墙只允许 Cloudflare 到 HTTPS，SSH 仅允许维护者固定来源或临时访问；
6. 在启用新服务前修改 Azure/Microsoft 密码、撤销旧会话、检查 MFA / OAuth 应用 / SSH 密钥，并轮换曾经暴露过的服务器凭据；
7. 先在测试子域名和测试账号验证注册、双设备修改、断网恢复、冲突、注销和数据删除，再切换正式域名。

2026-09-01 部署结果：私有管理员 hostname 已通过 Cloudflare 代理到独立的 Nginx server block，源站证书已按该 hostname 单独签发并启用自动续期；PaykiTodo API / Admin 服务运行在服务器 `127.0.0.1:18766`，不复用 1Panel，也不暴露后端端口。公网健康检查、账号注册/鉴权、管理员页面和管理操作均已验证。真实 hostname、证书路径、管理员密码和 Cloudflare 配置不进入 Git。

## 7. 分阶段实施

### Phase A：协议与本地队列

- 抽出 Android / Windows 共用 JSON DTO；
- Room 增加同步操作队列、服务端 revision、设备 ID 和墓碑；
- 所有待办 / 日程 / 规划文档写操作进入本地队列；
- 仍只使用测试服务器，保留现有 LAN 与快照恢复路径。

### Phase B：账号与双设备同步

- 实现注册、登录、刷新、设备撤销和加密密钥包装；
- 实现 push / pull / ack、幂等、断网重试和冲突提示；
- 手机与 Windows 各保留完整本地副本；
- 完成全字段 round-trip 和数据删除测试。

### Phase C：Windows 可写客户端

- WebView2 shell 连接本地 Windows 仓储而非只连接手机；
- 复用手机端字段契约和核心交互，但适配桌面布局；
- 云端不可用时仍可编辑并显示待同步状态；
- LAN 模式继续作为独立的手机直连入口。

### Phase D：管理员后台与正式部署

- 已完成独立管理员页面、用户/设备状态、快照元数据、存储统计、活跃时间和审计视图；停用用户、撤销设备和 CSRF 防护已落地。
- 已完成独立云服务、专用源站证书、Nginx `443` 反代和 Certbot 自动续期；现有 1Panel 与手机 LAN 服务保持独立。
- Cloudflare WAF / Rate Limiting、管理员 MFA、监控、灾备和密钥轮换仍是正式扩大用户范围前的安全增强项。
