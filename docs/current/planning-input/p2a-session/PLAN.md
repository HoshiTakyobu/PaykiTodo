# 规划输入讨论

## 当前版本
v0.5，基本字段、默认值、层级、引号、循环和多时段范围已确认；备注终止与跨午夜规则待回复。

## 目标
将每日看板的规划输入统一为临时编辑、识别、可修改预览和确认入库；无需 AI 即可使用，保留用户选择 AI 识别的能力。

## 非目标
不新增长期规划文档库，不以历史设计覆盖本轮用户要求，不在确认语法前实现新规则。

## 核心机制
使用 `- 任务名, @地点, 时间, (提醒1,提醒2);`，仅标题必填，日程起止用 `>`。日期简写按当前年/今天，日期时间支持空格及+。提醒省略默认5和0，空括号关闭。#表示备注；分号结束条目，无分号换行自动进入子级，有分号保持同级。

循环用每天/每N天/每周/每N周/每月/每年加方括号时段，多个时段共用标题、地点和提醒。范围可选 `自日期至日期` 或 `截至日期`，缺省从今天持续滚动生成；课程多时段保持关联，支持本次、某时段后续与整组修改。

标题/地点用首尾半角双引号保护分隔符，内部双引号保留。用户选择本地规则或已配置 AI 源；两条路径生成相同的候选结构，确认前不写待办或日程。

## 工作流
每日看板打开输入 → 识别 → 修改/取消候选 → 确认入库 → 清空本次草稿。

## 输出
双端及手机局域网兼容入口的统一实现、使用说明、测试和经过公开内容审计的提交。

## 当前风险
需要严格区分方括号、圆括号、引号内外的分隔符，错误定位不能丢原文。相对提醒缺时间基准、循环里的绝对提醒和字段首尾引号多解需要在实现契约中明确。快速清单父子关系与课程多时段关联不能意外丢失。既存规划原文和数据库必须保留，不能因取消新文档功能自动销毁历史数据。
