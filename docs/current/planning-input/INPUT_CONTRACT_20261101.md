# 规划输入契约：已确认规则与待定边界

这是供实现者使用的归一化契约。1.17.10已实现Android/Windows解析器和每日看板临时输入；LAN复用手机解析器。依据 [决策001–013](p2a-session/DECISIONS.md) 和用户最新回复；早期矛盾按后续明确回复覆盖。特别是“括号必须写”“空括号用默认提醒”“时间段是待办”都已被用户纠正。验收与当前边界见 [1.17.10记录](../VALIDATION_1.17.10.md)。

## 已确认：基本形式

```text
- 去超市购买水果, @永辉超市, 16:30, (5,15,120,11-02 12:00,2027-07-03 15:00);
```

| 项目 | 规则 |
| --- | --- |
| 标题 | 唯一必填字段，不能因为省略时间而拒绝创建 |
| 字段分隔 | 半角逗号；顶层半角分号结束条目 |
| 地点 | `@`识别，地点字段可省略 |
| 单个时间点 | TODO的DDL；可省略，省略即普通无DDL待办 |
| 起止时间 | EVENT，统一用 `>`；不再用 `-` 连接起止 |
| 日程额外待办 | 默认不创建日程结束待办或其他关联待办 |
| 备注 | 放在结束分号后，以 `#` 开始，直到该行末尾，归属前一条事项 |
| 多条事项 | 顶层分号分隔，同一行多个事项保持同级 |

允许的基本样例（未涉及待定备注边界）：

```text
- 整理书桌;
- 买水果, @超市;
- 交作业, 16:30;
- 阅读, 20:00, ();
- 讨论, @会议室, 14:00>15:00, (10,0);
- 整理报告, 11-02+12:00, (30,0);
- 跨日值班, 2026-11-01 14:00>2026-11-02 14:00;
```

省略字段不要求为它保留空逗号占位。`@`、时间形式、括号和循环表达用于识别可选字段。任意调换字段顺序、同类字段重复、空字段及标题中的裸`#`等尚未单独确认；应定义诊断或保守兼容，不能静默拼接成错误事项。

## 已确认：日期与时间

- 完整形式 `2026-11-01 02:25`。
- 当年可省略年份：`11-01 02:25`；日期与时间之间也支持 `+`，如 `11-02+12:00`。
- 无日期一律按照**今天**，不是每日看板选中日。省略年份一律按当前年，不因过去/未来自动跨年。
- 接受过去或未来时刻；过去提醒不补响。不能为迁就旧校验而要求“所有提醒必须晚于现在”。
- 日程两端分别解析，使用 `>`。明确跨日可直接写两端日期。
- `23:00>01:00`两端按今天解析后报错，提示补明确结束日期；用户已确认不自动改成次日。
- 测试应注入固定“今天”和时区，避免跨午夜导致两端样例产生不同结果。文档示例省略年份不表示只支持2026年。

## 已确认：提醒

| 写法 | 含义 |
| --- | --- |
| 省略提醒字段 | 默认 `(5,0)`；待办相对DDL、日程相对开始 |
| `()` | 明确不提醒 |
| `(5,15,0)` | 非负整数表示提前分钟数，0为到点 |
| `(11-02 12:00,2027-07-03 15:00,09:00)` | 绝对时刻，支持省略年份/日期及空格或+ |
| 混合列表 | 相对分钟与绝对时刻可以混用，不能丢掉绝对提醒 |

无DDL的标题待办必须可以创建；没有时间基准时，默认相对提醒不能被排到错误日期。显式相对提醒却没写时间、循环中的绝对提醒如何分配仍需明确，见后文。

## 已确认：层级与输入辅助

- 上一行**无顶层分号**时按Enter：自动增加一级缩进并插入 `-`。
- 上一行**有顶层分号**时按Enter：保持当前层级并插入 `-`，不是自动回到最外层。
- Shift+Tab或手机“减少缩进”返回一级；同一行分号后的事项是同级。
- 引号内、括号内的分号不能误判为已结束条目。粘贴多行与键盘逐行输入的解析应一致。
- 实际父子待办必须落库并保留折叠/完成行为，不依赖保存原规划文档来维持关系。

示例层级：

```text
- 准备出行
  - 买车票, 18:00;
  - 收拾行李;
- 阅读;
```

父节点自身也有类型/时间、日程下的子任务、取消选中父候选后的孩子归属尚无完整交互合同。保留用户输入并在预览明确结果，不自动把父节点变成无关文档或丢失孩子。

## 已确认：标题与地点中的标点和引号

标题或地点包含半角逗号、分号时允许用半角双引号包裹：

```text
- "买苹果,香蕉", @超市, 16:30, ();
- "讨论;整理", @"教学楼,201", 14:00>15:00;
```

用户要求保留字段内部的半角双引号，匹配字段首尾双引号，不要求逐个输入转义字符。因此不能遇到每个 `"` 就机械切换“引号内/外”状态。示意标题 `"阅读"重点",并整理"` 应按字段首尾引号考虑，内部内容不能丢失。

如果多个字段边界都能形成有效解释，应给出定位诊断并让用户在预览修正；“匹配首尾”不是取整行第一个和最后一个引号，把中间多个字段吞成一个标题。

## 已确认：循环与多时段

循环是时间字段的扩展，不另开一套文档语法：

```text
每天[08:00>08:30]
每2天[08:00>08:30]
每周[周一 08:00>09:40, 周三 14:00>15:40]
每2周[周一 08:00>09:40, 周三 14:00>15:40]
每月[15日 09:00>10:00]
每年[11-01 09:00>10:00]
```

例如：

```text
- 高等数学, @教学楼201, 每周[周一 08:00>09:40, 周三 14:00>15:40], (10,0), 自2026-11-01至2027-01-15;
- 散步, 每天[20:00>20:30];
```

- 方括号内多个时段属于同一项安排，共用外部标题、地点和提醒。
- 可选范围字段为 `自2026-11-01至2027-01-15` 或 `截至2027-01-15`。
- 省略范围时从今天开始、持续重复；展示/生成窗口不等于截止。不得把90天写入隐含结束日期。
- 同一课程的时段保持关联，可只改本次、某一时段的后续或整门课程全部时段，共用字段可统一修改。
- 用户确认的最小范围是循环**日程**。循环待办、每月多个日期、隔N月/隔N年、农历等扩展不能因为底层支持就擅自改变主语法；旧业务能力可继续兼容。

## 仍待确认或明确的边界

| 问题 | 当前状态 | 建议，尚非用户确认 |
| --- | --- | --- |
| 备注与终止分号 | 已确认 | 规范 `- 阅读,16:30,(); #先读第二章`；#之后直到行尾是前一条备注，内部逗号/分号/引号保留 |
| `23:00>01:00` | 已确认 | 按两端都今天判错，提示补明确结束日期，不自动次日 |

| 循环里的绝对提醒 | 等待用户选择归属 | 已提问“仅归属该时刻之后最近一次课程”或“循环只允许提前分钟”；未答复。当前定位报错并保留原文，暂不导入，不能复制同一绝对时刻到所有实例 |
| 月末、闰日、间隔锚点 | 1.17.10沿用CLAMP | 月末/闰日使用实际月份末日，配置意图日保留；预览明确说明。每2周按同一生效周安排各时段，保持间隔 |
| 引号多解、非法字段与半条输入 | 1.17.10诊断 | 保留原文、显示行列、返回原文修复；诊断未清除时不允许整批确认。预览可直接修改有效候选，不静默导入坏行 |

实现层级合同：父候选按稳定ID关联；取消选中父事项时，子候选须另选父事项或变为顶层，否则导入报错且事务不写入。循环或日程父项目前关联其首个实例，不能把这个关联宣称为每次实例都复制孩子。预览允许改变时间表达式，从待办转日程或清空成为普通待办。新导入只选个人日历，共享日程继续走日历中的权限流程。

## 必须覆盖的验收样例

仅标题；省略地点/时间/提醒；默认5和0；空括号关闭；相对/绝对/混合提醒；过去时刻不补响；今天与看板选中日不同；年末不自动跨年；空格/+；明确跨日；同一行多个事项；嵌套任务及回退缩进；带逗号/分号/内部引号的标题地点；非法输入有定位；每天/每N天/每周/每N周/每月/每年；有范围和无限循环；同课不同周时段及三种修改范围；AI候选和本地候选同样校验；取消和识别不写库；确认只导入一次；手机、Windows、迁移包往返仍保留提醒/层级/课程关联。
