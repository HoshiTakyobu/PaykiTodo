# 规划输入决策

实现时先读 [归一化输入契约](../INPUT_CONTRACT_20261101.md)。本文件保留决策历史：003/004中的括号与时间段解释已被005/006/008的明确回复覆盖，不能把早期“已确认”标签当作当前规范。最初2026-11-01交接未引入新选择；后续循环绝对提醒的本轮执行规则及来源记录在014，不伪造用户数字选项回复。

## 决策 001

问题：入口及持久化方式。

用户选择：移入每日看板，替代快速待办清单入口，取消独立规划模块、新建文档和保存历史流程。

理由：规划文本最终转成长期保存的待办和日程，无需重复的文档管理。

计划影响：候选确认后才写数据库，新输入使用临时草稿。既存数据的恢复兼容性须保留。

状态：已确认（本轮原始需求）。

## 决策 002

问题：识别方式与用户确认。

用户选择：本地语法无需 AI；保留可选 AI；必须可预览、直接修改并确认后入库；新语法先讨论。

理由：可独立使用并控制识别准确度。

计划影响：语法问题未收到回复前保持待定，其他明确修改继续实施。

状态：已确认（本轮原始需求）。

## 决策 003

问题：主要输入语法。

用户选择：`- 任务名, @地点, 时间, (提醒1,提醒2);`。半角逗号分字段，半角括号必须存在，括号内用半角逗号分隔提醒，半角分号结束条目。任务名不限制内容，地点以 @ 为标记。

日期完整写法为 `2026-11-01 02:25`；当年省略年份，当年当天省略日期。允许过去或未来时间，不擅自改年。日程起止用 `>`，例如 `2026-11-01 14:00>2026-11-02 14:00`。用户同时举出 `16:30-18:00` 为待办时间段，具体含义待下一轮确认。

提醒支持非负整数（提前分钟数）、完整日期时间、无年份日期时间、仅时间。用户原例包含相对与绝对提醒混用。

换行：上一行无分号时自动缩进并插入短横线，有分号则插入同级条目。退回上级操作和同一行多个条目的边界待确认。

理由：用户用固定分隔格式快速批量录入，保留日期简写与层级输入。

计划影响：废弃本轮助手提出的中文字段主语法建议，解析器、预览和教程基于用户格式实现；不把尚未确定的时间段与空提醒语义写死。

状态：字段标记与基本日期规则已确认；歧义另列开放问题。

## 决策 004

问题：省略日期与提醒的默认行为。

用户选择：无日期全部按今天；日程不自动创建待办；未写提醒时间时，待办默认提前5分钟及DDL时刻，日程默认提前5分钟及开始时刻。

理由：用户明确要求两次提醒且不增加冗余待办。

计划影响：空括号 `()` 使用 `(5,0)` 的默认语义，覆盖助手待回复问题中的空括号关闭提醒建议；关闭提醒可在预览中完成。日期不继承看板选中日。

状态：已确认。

## 决策 005

问题：事项类型、说明文字和日期连接。

用户选择：先前“时间段即为待办”为笔误。时间点是待办，时间段是日程，起止只用 `>`，不使用 `-`。说明文字一律以 `#` 跟在条目后。日期和时间支持空格或 `+`。

理由：统一明确的类型标记，兼顾日期输入习惯。

计划影响：不新增有开始/截止双时间的待办类型。绝对时间按原样保留，过去提醒不补响。后续样例说明 # 与条目终止分号的顺序。

状态：已确认。用户同时选择了含“空括号不提醒”的选项，与决策004存在歧义，已用专门问题澄清，决策004中的空括号解释暂不可作为实现依据。

## 决策 006

问题：提醒字段与空括号冲突。

用户选择：括号可省略，省略时默认两次提醒；显式 `()` 不提醒。

理由：同时提供快捷默认与明确关闭的写法。

计划影响：替代决策003“括号必须存在”和决策004“空括号默认”两处旧解释；默认提醒为 `(5,0)`，显式列表以用户输入为准。

状态：已确认。

## 决策 007

问题：层级及字段内标点。

用户选择：无分号换行进入子级，有分号保持当前级；Shift+Tab 或手机减少缩进回上一级；同一行分号后的条目保持同级。标题/地点内有半角逗号或分号可用半角双引号包裹，内部仍有双引号时匹配字段首尾双引号，保留内部引号。

理由：支持自然标题内容与快速父子输入，不要求为内部引号逐个输入转义符。

计划影响：解析器需识别括号/字段引号内的分隔符，不能直接按逗号或分号 Split；有多个有效解读时应要求用户预览修正，不能静默丢字。

状态：已确认。

## 决策 008

问题：必填字段与高级循环表达。

用户选择：只有标题必填，发生时间、地点、提醒都可缺省。语法必须支持循环日程，以及同一个安排在每周多个不同时段执行，例如同一门课程。

理由：日常简写应轻便，也要覆盖课程表等持续安排。

计划影响：允许仅标题待办；缺少时间无法确定提醒基准时需明确说明。新增循环表达及多时段解析、预览和导入，不能仅支持单次日程后就视为完成。

状态：范围已确认，具体循环写法讨论中。

## 决策 009

问题：循环生效范围。

用户选择：可选字段 `自2026-11-01至2027-01-15` 或 `截至2027-01-15`。省略范围从今天开始持续重复，预览近期实例，之后持续生成，不以90天作为隐含截止。

理由：课程可指定学期，长期习惯无需人为终止。

计划影响：多时段导入不能沿用现有函数默认的90天终止日期；滚动生成窗口与循环截止需区分。

状态：已确认。

## 决策 010

问题：每周多个时段导入后的关联。

用户选择：作为同一组课程管理，可只改本次、某一时段的后续或整门课程的全部时段，共用字段可统一修改。

理由：同一门课不能在导入后失去整体管理能力。

计划影响：保留 multiSlotBundleId 等关联，补齐双端课程整体编辑入口和作用域，验证时间变更不会错误覆盖另一个时段。

状态：已确认。

## 决策 011

问题：循环时间字段的具体写法。

用户选择：`每天[08:00>08:30]`、`每2天[08:00>08:30]`、`每周[周一 08:00>09:40, 周三 14:00>15:40]`、`每2周[...]`、`每月[15日 09:00>10:00]`、`每年[11-01 09:00>10:00]`。方括号内多个时段属于同一项安排，共用外部标题、地点和提醒。

理由：扩展时间字段即可表示循环，不增加另一套录入流程。

计划影响：词法分析同时保护引号、圆括号、方括号中的分隔符；解析器与AI候选合同包含循环、间隔、多时段和可选范围。

状态：已确认。

## 决策 012

问题：#备注和结束分号的先后。

用户选择：分号后，`- 阅读,16:30; #先读第二章`。

计划影响：备注归属刚结束的前一条事项，#之后直到该行末尾全部保留，内部标点不再分任务。

状态：已确认，2026-11-01恢复执行时答复。

## 决策 013

问题：无日期的23:00>01:00是否自动跨午夜。

用户选择：提示补结束日期，不自动改成次日。

计划影响：两端各自继承今天，结束不晚于开始时定位报错；显式跨日日期正常接受。

状态：已确认，2026-11-01恢复执行时答复。

## 决策 014

问题：同一循环课程的多个时段如何处理显式绝对提醒。

决定来源：本轮按最后单一推荐方案后用户继续执行，采用绝对时刻只提醒一次、归属之后最近一次课程的方案。此前没有收到数字选项回复，本记录不将“继续”写成用户明确提交了某个数字选项。

本轮执行规则：对每个不同绝对时刻，在整门课程所有输入时段的合法实例中，选择开始时刻Start>=absolute的最近一个。相等归该实例；多个最早开始时刻并列时，按方括号内输入时段的顺序选择唯一实例。相对分钟仍针对每次课程，绝对时刻原样保留且过去不补响。

范围与数据影响：查询不受首批预览/生成窗口限制，窗口外目标必须正确生成；有限范围内无合法目标时定位报错、保留原文并拒绝部分导入。重复绝对时刻去重，不按每个时段各保存一次，不自动拆出隐含待办。循环补齐及实例修改继续保留已有拥有者，不能复制或自动重新分配单次提醒。

AI合同影响：保留一门课程的所有时段及原始提醒表达，由共用解析和导入完成唯一归属；AI不得展开所有重复实例、扩散绝对提醒、编造目标或另建单次事项来掩盖无目标错误。

状态：本轮按上述来源执行；新分支完成与通过情况以独立的双端验收记录为准。
